## Tomorrow's rules (luma.com/finch-jd7i, crewbasecollective.com/aim-hack-visual)
- Bruin is MANDATORY for every project; other sponsors only qualify for their own prize if used. Use AdaL to make the demo video.
- Must-haves: visible characters, visual output, movement/action on screen, 3+ agents with own goals, visible decision log. Scores higher: 3D, ML/trained agents (RL, fine-tuning, memory that changes decisions), voice.
- Submit: public repo, 1-3 min demo video and/or live link, which sponsor tools you used and how. Code written on the day.
- Prizes: Bruin 1st $1000 / 2nd $500; BAND $500; Lingcode $200; AdaL Pro 1yr/6mo/3mo; Telem $500/$300/$100; Runware $200; Glasser $100; Teamily, Casuro TBD.

## Patterns that win
1. The demo is the product. Cal Hacks 12 grand-prize winner: focus everything on a user story and demo, dedicate one person to UI, keep a hardcoded fallback, cut features that fail on camera (they removed clicking). Source: blog.dylanlu.com/cal-hacks-12.
2. Make the abstract spatial or visual. Conjure (LA Hacks 1st) turned agent search into a walkable 3D world; Edith ran on glasses; SearchHack entries used Three.js animal agents and 3D evidence graphs. Tomorrow's rubric also says 3D scores higher.
3. Use sponsor tools deeply and say how. Sponsor prizes are "best use": Fetch.ai's One Agent Workflow went to HackOverflow for real inter-agent communication; Runpod's winners ran real GPU workloads. Tomorrow Bruin is mandatory with the biggest prizes, so put it in the core loop, not a bolt-on. The submission form asks which tools you used and how.
4. Loops that close and improve: Nomen (research, generate, publish, learn from performance), Aetheris (RL loop), Talos (diagnose, fix, independently verify). Tomorrow's ML bonus: memory that changes decisions.
5. Built-in checks and visible reasoning: TalosAI could not approve its own work; SearchHack projects verified claims across engines; tomorrow requires a decision ledger. Show why agents decided.
6. Real, specific user and data: Dots (ADA rule), Senna (dispatchers' real software), CrossBeam (permitting), Agentropolis (real Toronto). Generic "agents chatting" lost to specifics.
7. Beat prior winners, avoid chatbot clones: the Cal Hacks winner checked past Devpost winners and judged ASU entries as "almost every project a chatbot clone".
8. Persistence and narrow scope: Aetheris lost, then won a sponsor prize, then the grand prize. Dots: "tight scope, real impact". Pick one track, make one loop flawless.
9. Film (track 1): choose a style that hides model weaknesses (claymation), give precise parameters not mood words, separate idea/tech/editor roles with a coach agent that cannot edit, pass file paths between agents (Google crews). Tomorrow requires different endings from the same setup, so show two runs.
10. Winners are often small young teams shipping in hours (three 15 year olds, solo builders). Scope for a day.

## What to avoid
- A chatbot or text-only agent chat with no moving characters: fails tomorrow's hard must-haves.
- Skipping Bruin: it is mandatory, so the project may not qualify.
- Features that only work sometimes: record a demo video as backup (submission accepts video).
- Thin sponsor name-drops (one call each). Judges include sponsor staff who know their product.
- Generic pitches with no concrete user or evidence; claiming "unscripted" without showing the log and a second run with a different outcome.
- Over-scoping (thousands of agents, three tracks, heavy infra): show 3-5 agents clearly.
- Leaving before judging, or relying on judges to infer value: present it yourself.
